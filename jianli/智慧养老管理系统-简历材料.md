## 一、后端知识点清单(含"在哪、怎么答")

### 1. 框架与工程分层
| 知识点 | 项目体现 | 面试怎么讲 |
| --- | --- | --- |
| Spring Boot 3(JDK 21) | pom:spring-boot-starter-web、starter;`application.yml` 配置 | 起步依赖、自动配置、内置 Tomcat、端口/数据源配置 |
| 三层/四层分层 | controller → service(接口+Impl) → mapper;entity/query/dto/vo 分层放 pojo | 职责单一、依赖方向、扩展点(接口先行的 Service 设计) |
| 统一返回体 | `util/Result<T>`(code=1/0 + msg + data) | 前后端约定、code 语义、避免直接抛异常给前端 |
| 全局异常处理 | `@RestControllerAdvice` GlobalExceptionHandler:业务异常 ServiceException 与兜底 Exception 分开处理 | 异常分类:主动抛业务异常给用户看,意外异常记日志不泄露堆栈 |
| Lombok | `@Data/@Slf4j` | 减少样板代码;注意 @EqualsAndHashCode(callSuper) 用法 |

## 二、可改进点(主动讲 = 加分)

> 面试技巧:这些不是"你项目有问题",而是"你清楚边界、有下一步规划"。选 2~4 个讲即可。

### 安全(最优先)
1. **密码明文存储 → 改为 BCrypt 加密**(user/elder 表当前明文、equalsIgnoreCase 比对)。
2. **方法级权限校验**:现在只做登录拦截,未做接口级权限;可引入自定义注解 + AOP 按 `permission_value` 校验,或在 Controller 拦截器里加载角色权限白名单。
3. 敏感信息脱敏:身份证/手机号展示脱敏;接口不返回 password(userInfo 已置空,可统一用 @JsonIgnore)。
4. AI 安全:限制单用户频率、内容长度已做;后续可加敏感词/工具调用的二次授权确认。

### 架构与工程
5. 当前用户信息放 `ThreadLocal`(UserContext)统一取,而不是每个 Controller 手动 `JwtUtil.parseToken(token)`。
6. Spring profiles(dev/prod 数据源、日志分级)、配置加密(OSS key 若硬编码需外移环境变量,勿进 git)。
7. 引入接口文档(springdoc-openapi/Swagger)与统一响应 DTO 校验(`@Valid` + validation)。
8. 补充单元测试/接口测试(MockMvc + Testcontainers 或 H2),覆盖率看核心 Service;CI(GitHub Actions:compile + test + build)。

### 业务正确性(这个项目真实存在的点,讲出来很加分)
9. **护理计划生成任务的逻辑只生成了"开始日期当天"的任务**:明细里 execute_cycle(天/周/月)与 execute_frequency 字段存在但未真正按周期批量展开。改进:按 周期×频次×计划日期范围 生成未来任务,并用定时任务(@Scheduled)每日把到期任务生成/预生成,过期补单。
10. 并发一致性:护理任务完成打卡、退住结算等场景可加乐观锁(@Version)或状态机校验,防止重复打卡/重复退住。
11. 权限树/角色赋值用"先删后插",数据量大后可改批量 insert;事务已加,建议补充 @Transactional(rollbackFor)。

### 性能
12. 统计/趋势 SQL 加索引:care_task(plan_execute_date, status)、elder(status, birthday)、care_plan(elder_id, status)。
13. 大字段/图片走 CDN + 压缩;上传限制类型白名单 + 大小限制(已有 10MB)。
14. 前端:路由懒加载已做;Element Plus 可再按需引入进一步减主包;列表页加 v-loading 与空态。

### AI 助手二期(呼应你已在做的功能)
15. 流式输出(SSE)提升体验;用 spring-ai ChatMemory 管理多轮(依赖已引入)。
16. 真正的工具调用(function calling):"设置用药提醒 / 联系家属 / 社区紧急呼叫",必须"用户授权 + 工具真实执行成功"才允许 AI 宣称完成(和提示词要求一致)。
17. 健康上下文时效:护理记录/体检数据量大后做索引与"只取最近 N 天/最近一次体检"的查询边界。

## 三、简历项目介绍

### 版本 A(综合版,推荐用于投递 Java 后端)

> **智慧养老管理系统(前后端分离全栈项目)**
> **技术栈**:Spring Boot 3 / MyBatis-Plus / MySQL 8 / JWT / EasyExcel / 阿里云 OSS / Vue3 + Element Plus / Vant / Pinia / ECharts / 阿里云百炼大模型(Spring AI)
> **职责与成果**:
> - 独立完成系统设计与开发:设计 18 张库表(RBAC 权限、老人档案与标签、护理计划/任务主从表、体检套餐与预约/结果记录),明确状态枚举与冗余快照策略(项目/套餐名称快照保证历史数据不被改名影响)。
> - 后端基于 Spring Boot + MyBatis-Plus 分层实现:统一 Result 返回、@RestControllerAdvice 全局异常处理、JWT + 拦截器登录鉴权;LambdaQueryWrapper 空值短路条件查询、分页插件、逻辑删除、字段自动填充;护理计划新增/修改/删除用 @Transactional 级联维护明细与护理任务,并按计划明细生成"打卡式"护理任务。
> - 基于 RBAC 实现动态菜单与按钮权限:permission 表承载目录/菜单/按钮树,登录后按角色 JOIN 查询返回 routerList + btnList,前端据此渲染侧边栏与控制按钮显隐。
> - 实现基于 EasyExcel 的用户导入导出与阿里云 OSS 图片上传;提供聚合统计接口(CASE WHEN/GROUP BY/日期区间)支撑 ECharts 数据看板。
> - 近期接入大模型:复用百炼(spring.ai.dashscope + qwen-plus),实现面向老人端的"康养小智"健康助手——服务端只读组装该用户健康档案上下文,以 OpenAI 兼容协议对话,并按医疗安全人设(不替代医生、紧急话术、禁止虚构执行结果)约束回复。
> - 前端完成 Vue3 + Element Plus 后台与 Vant 移动端的页面开发与重构:登录、老人/护理/体检/权限等业务模块 CRUD、首页数据看板、AI 对话页;路由懒加载分包,构建产物主包从约 1.3MB 降至 1.2MB 且各页面独立 chunk。

### 版本 B(一句话定位)
> 面向养老院的 Java 全栈管理系统:后端 Spring Boot3 + MyBatis-Plus 覆盖 RBAC 动态权限、老人档案、护理计划→任务执行闭环、体检预约与结果记录;并集成阿里云百炼大模型做老人端 AI 健康助手(带健康档案上下文与安全人设),前端 Vue3 双端(Element Plus 后台 / Vant H5)。

### 可写进"项目难点/亮点"的候选句(挑 2~3 个,别全抄)
1. "动态权限:权限表自关联建树,登录后按用户聚合权限返回菜单树与按钮码,前端按码控制按钮显隐。"

5. "统计可视化:纯 SQL 聚合(CASE 分桶/日期区间)+ Service 补零,一次接口返回多图数据;前端 ECharts 按需注册,懒加载分包。"
